# Architecture rules
- Keep public trainer brand styling opt-in through scoped tokens and font aliases; shared consumer/admin/dashboard styling must not inherit trainer-only changes.
- The shared language selector accepts an opt-in trainer theme, including its portalled menu, so both public audiences keep one language implementation.
- Keep the trainer hero preview self-contained in components/hero with scoped semantic CSS tokens; use one visibility observer and respect reduced motion so the illustration never affects live dashboard state.
- Store complete marketplace demo records separately from the legacy Trainer adapter so the marketplace can use structured credentials and history without changing the existing profile rendering.
- Keep marketplace-only presentation scoped under trainer-market and reuse public brand tokens to isolate other pages.
- Share the public marketplace presentation across audience-specific page wrappers; select shells and demo interaction gates by audience so consumer discovery never navigates into trainer marketing.
- Keep PublicHeader presentation scoped to public trainer profiles, with active tab state owned by the page and optional tabs derived from trainer records, so future tab bodies can reuse the same selection without changing lookup logic.
- Keep package/class bodies in PublicOfferTabs using structured trainer records and computed seat states; carry offer context through page-owned selection into the shared booking dialog so registration does not discard it.
- Render public experience, education, reviews and availability in PublicDetailTabs, never a second tab system; demo schedules derive upcoming dates from each record's weekly pattern to prevent stale dates and closed-day bookings.
- Keep home-page feature cards generated from one array of translation-key/icon pairs in components/home, so adding a card is a data edit and never a hand-written JSX block.
- Keep the home walkthrough phone presentational and driven by section-owned step state; stop automatic rotation after manual selection and under reduced motion to preserve user control without touching live application data.
- Mount one language-parameterized trainer home for both language URLs; derive home context from the pathname and persist only explicit selections to avoid duplicated content and redirect loops. Update home html language and canonical/alternate links directly in a language-dependent effect, reusing tags by selector so production navigation does not depend on Helmet or accumulate tags.
- Market variants such as India are extra locales built as a base dictionary plus overrides (translations/in.ts), with demo names and amounts in translation keys, so a new market never forks page components.
